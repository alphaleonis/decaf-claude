# subagent agent-a1bea1a5f9dbac2e8

## Issues Found

**1. Querier closed before its returned `ChunkSeriesSet` is iterated — use-after-close on lazily-read index/chunk data**

- **File/line:** `storage/remote/read_handler.go:242-266` (the `defer func() { querier.Close() ... }()` at lines 247-251, combined with the `return querier.Select(...)` at line 265), called from line 205 in `remoteReadStreamedXORChunks`.
- **Why it's a bug:** `getChunkSeriesSet` now closes the querier via `defer` as soon as the function returns — i.e. immediately after `querier.Select(...)` produces a `ChunkSeriesSet`, and *before* that series set is ever iterated. But `Select()` for TSDB-backed queriers is lazy: `tsdb.DB.ChunkQuerier` returns a `storage.NewMergeChunkQuerier` of per-block `blockChunkQuerier`s (`tsdb/db.go:2067-2072`); `blockChunkQuerier.Select` (`tsdb/querier.go:174-196`) just wraps the block's `index`, `chunks`, and `tombstones` readers into a `blockChunkSeriesSet`/`blockBaseSeriesSet` without reading anything. The actual reads happen later, in `blockBaseSeriesSet.Next()` (`tsdb/querier.go:558-560`, `b.index.Series(...)`) and in the tombstone/chunk iterator paths — which are only invoked when the caller drives the set with `ss.Next()`/`ss.At()`. That driving happens back in `remoteReadStreamedXORChunks` → `StreamChunkedReadResponses` (`storage/remote/codec.go:235-296`), i.e. strictly *after* `getChunkSeriesSet` has already returned and closed the querier.
  `blockBaseQuerier.Close()` (`tsdb/querier.go:103-115`) closes `q.index`, `q.chunks`, and `q.tombstones`, and the index reader's `Close()` (`tsdb/index/index.go:1480-1482`) closes the underlying (mmap-backed) byte slice. So by the time `StreamChunkedReadResponses` calls `ss.Next()`, it is reading from a closed/unmapped index and chunk reader — a genuine use-after-close bug (best case: spurious "already closed"/read errors; worst case with mmap: reading unmapped memory). This directly defeats the previous (correct) behavior, where the `defer querier.Close()` lived in the outer closure and only ran after `StreamChunkedReadResponses` had fully consumed the series set. The PR's stated goal ("close the querier earlier") is achieved, but at the cost of closing it *too* early — before, not after, consumption of the data it produced.
- No unit test in this PR/file catches it because the existing tests use an in-memory mock `Queryable`/`ChunkSeriesSet` rather than a real TSDB-backed querier with mmap'd/closable readers, so premature `Close()` there is a no-op.

No other issues (error propagation, warnings, and double-close/missing-close) were introduced by this diff — the `chunks.Err()` check added at line 206 and the final `ss.Err()`/warnings handling in `StreamChunkedReadResponses` are unaffected and correct.
