- **Error class shape (`this.name = 'ClassName'` set in constructor)** — `StreamIdleTimeoutError` matches the convention established by `platform/authentication/common/authentication.ts:32` (`MinimalModeError`) and `platform/parser/node/parserService.ts:121-126` (`ParserWorkerTimeoutError`, itself a timeout-error sibling with the identical `constructor() { super(...); this.name = '...'; }` shape). No drift.
- **Constant naming/placement (`SSE_FIRST_CHUNK_TIMEOUT_MS`, `SSE_IDLE_TIMEOUT_MS`)** — no comparable `_TIMEOUT_MS` constant pair exists elsewhere in `platform/*` to establish a naming/placement convention against (only `INACTIVE_TIMEOUT` in `platform/survey/vscode/surveyServiceImpl.ts:22` and one `timeoutMs` parameter default in `platform/editing/common/edit.ts:12`, neither exported nor `_MS`-suffixed). First-of-kind; not flagged.
- **Test suite naming style in `streamIdleTimeout.spec.ts`** (`suite('withStreamIdleTimeout', () => {...})`) — sibling files in the same directory disagree: `networking.spec.ts:16` and `fetcherFallback.spec.ts:19` use `'X Test Suite'` + `function()`, but `headerContributors.spec.ts:12` uses a bare descriptive name + arrow function, matching the new file. Convention doesn't hold across the codebase (confirmed by a broader `suite(` grep showing both styles throughout `platform/*`), so not reportable.
- **Fake-timer usage (`vi.useFakeTimers()` in `beforeEach`/`afterEach`)** — matches the pattern used in several other `.spec.ts` files (e.g. `extension/chatSessions/common/test/ttlCache.spec.ts`). Consistent, not flagged.
- **`extChatEndpoint.ts:210` (`for await (const chunk of response.stream)`)** — `response` here is `vscode.LanguageModelChatResponse`, an unrelated VS Code API type, not a `DestroyableStream`. No sibling relationship to the changed code; correctly out of scope.
