## Considered But Not Flagged

- Shared `topologyLabels` map passed to multiple proxiers (metaProxier fans it to ipv4+ipv6): `handleNodeEvent` allocates a fresh map per event and never mutates a previously-handed-out map; each proxier stores/reads it under its own `mu`. No concurrent mutation — scenario fell apart at "map is mutated after sharing" (it isn't).
- NodeTopologyConfig DeleteFunc is a no-op (topology labels never cleared on delete): on any real node delete the shared informer also drives NodeManager.OnNodeDelete → os.Exit, so the process dies before stale labels matter. Step "process survives the delete" fails.
- `klog.Flush()` + `os.Exit` racing concurrent proxier sync: iptables (iptables-restore) and nftables (single netlink txn) apply atomically, so an abrupt exit does not leave a half-written ruleset. Only winkernel's incremental HNS updates could tear, but OnTopologyChange there is a no-op and state reconciles on restart — no concrete corruption path.
- NodeManager.Node() nil-deref in health server: `node` is guaranteed non-nil after successful construction and every OnNodeChange assigns a non-nil event object; no reachable nil path.
- Resync/relist producing spurious NodeIP "change": synthetic resync Updates carry the same object (old==new), DeepEqual holds, no crash. Only the empty-list Delete case (reported above) survives.
