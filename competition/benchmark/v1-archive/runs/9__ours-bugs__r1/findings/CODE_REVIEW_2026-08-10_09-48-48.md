## Minor Findings

### Consistency

- `pkg/proxy/config/config.go:503` — `NodeTopologyConfig.listerSynced` is assigned (`= handlerRegistration.HasSynced`) but **never read**. The sibling configs (`EndpointSliceConfig`, `ServiceConfig`, `NodeConfig`, `ServiceCIDRConfig`) each wire `listerSynced` into a `Run()`/`WaitForNamedCacheSync`; `NodeTopologyConfig` has neither, so the field is dead. Harmless (the handler fires directly off the already-synced shared informer), but it breaks the established sibling pattern and reads as an unfinished `Run()`. (adversarial-reviewer, orchestrator)
- `pkg/proxy/config/config.go:320` — `handleChangeNode` contains a `cache.DeletedFinalStateUnknown` tombstone branch, but it is wired only as the informer's `UpdateFunc`. Tombstones are delivered exclusively to `DeleteFunc`, so the branch is unreachable dead code (copied from the delete path). (broad-reviewer, quick-reviewer, go-reviewer)
- `pkg/proxy/node.go:130` — `NodeManager.PodCIDRs()` returns `n.node.Spec.PodCIDRs` directly (the internal/informer-cache-backed slice), whereas `Node()` deep-copies and `NodeIPs()` returns a freshly built slice. Inconsistent copy semantics; a latent aliasing hazard. Not currently triggered — the sole consumer `s.podCIDRs` is read-only (`server.go:293,343`, `server_linux.go:130`) and never mutated. (broad-reviewer, go-reviewer)

### Residual Risks

- `pkg/proxy/healthcheck/proxy_health.go:176` — `NodeEligible()` acquires the exclusive `hs.lock.Lock()` but reads no field that lock protects (`lastUpdatedMap` / `oldestPendingQueuedMap`); it only reads `hs.nodeManager` and calls `nodeManager.Node()` (self-synchronized). An `RLock` — or no `hs.lock` at all — would suffice; the exclusive lock needlessly serializes health-eligibility reads against health-status updates. Minor perf, no correctness impact (the pre-refactor code used `RLock`). (quick-reviewer, broad-reviewer)
- `pkg/proxy/node.go:158` — `OnNodeChange` replaces the stored node (`n.node = node`) **before** validating the incoming node's IPs, and ignores the error from the old-value read (`oldNodeIPs, _ := utilnode.GetNodeHostIPs(n.node)`). If an Update carries a node that transiently has no parseable addresses, that IP-less node is stored and the handler returns without exiting; a subsequent Update that restores the original IP then computes `oldNodeIPs = nil` (error swallowed) and `reflect.DeepEqual(nil, restoredIPs) == false` → spurious `os.Exit(1)`/restart, even though the effective node IP never changed. Low probability (kubelet effectively always reports an InternalIP) and the consequence is a fail-safe restart, but it is a real logic flaw introduced here. Fix: read old IPs before swapping and only compare when both reads succeed. (go-reviewer)
- `pkg/proxy/node.go:154` / `cmd/kube-proxy/app/server.go:608` — the `NodeManager` handler is registered on the informer via `NewNodeConfig`, which wires only `UpdateFunc`+`DeleteFunc` (no `AddFunc`). Because the informer is already started and synced inside `NewNodeManager`, client-go **replays the current node as an Add** to the newly-registered handler — and that replay is discarded (no `AddFunc`). If the node's IP changes in the sub-second window between the initial poll capture (`NewNodeManager`) and handler registration (`server.Run`), the change is invisible until the next real Update; meanwhile the proxier was built from the stale NodeIP. Rare startup race; self-heals (late) on the next Update. Fix: reconcile the current lister state after registering the handler, or route Add through `OnNodeChange`. (adversarial-reviewer)

## Specialist Notes

### Considered But Not Flagged (all agents)

- **Address-reordering spurious exit** (adversarial-reviewer, conf 50; `node.go`): claimed that reordering `node.Status.Addresses` flips `GetNodeHostIPs` output and triggers `os.Exit`. Verified against `pkg/util/node/node.go`: the output is `[first InternalIP-or-ExternalIP, first IP of the other family]`. A reorder that changes this result reflects a genuine change of the primary/secondary node IP — which the design intends to restart on. Pure same-set reordering that preserves the first-of-each-family produces an identical result. Not a spurious exit; dismissed.
- **`NodeIPs()` swallows `GetNodeHostIPs` error** (go-reviewer, Medium conf 75; `node.go:123`): at its only call site (`server.go:218`) the node was already validated to have retrievable IPs by the `NewNodeManager` poll, so the error path is unreachable there. Latent only.
- **`NodeTopologyConfig.handleNodeEvent` mutates `topologyLabels` without a mutex** (go-reviewer, conf 50; `config.go`): client-go delivers events to a single handler registration sequentially from one goroutine, so `handleNodeEvent` never overlaps itself; the map it hands to proxiers is freshly allocated each call. No concurrent access → no data race. Dismissed (go-reviewer self-rated it a design note).
- **Nil `nodeManager` deref in `NodeEligible()`** (quick-reviewer & adversarial-reviewer, conf 50; `proxy_health.go`): the health server is created only when `HealthzBindAddress` is set, and `NewNodeManager` errors abort `newProxyServer` before the health server is built, so `nodeManager` (and `n.node`, guaranteed by the poll) is non-nil wherever `NodeEligible` runs. Construction ordering makes it safe; dismissed. (A defensive nil check remains a reasonable hardening, but no current path triggers it.)
- **`NewNodeManager` cache-sync has no independent timeout** (broad-reviewer): `WaitForNamedCacheSync` blocks on `ctx.Done()`; if the API server is unreachable, startup blocks. This is the standard kube-proxy/informer pattern and pre-existing behavior, not introduced by this change → `pre-existing, out of reach` under `reach=narrow`.
- **`OnNodeChange` exit decision computed after `mu` is unlocked** (adversarial-reviewer): safe — the values used for the exit decision are read under the lock (or are the local event argument); the lock only guards concurrent `Node()`/`NodeIPs()`/`PodCIDRs()` readers, and the handler is single-threaded.
