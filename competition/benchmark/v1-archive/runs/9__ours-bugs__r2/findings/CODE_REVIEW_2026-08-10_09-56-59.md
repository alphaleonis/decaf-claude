## Findings

### #1 🟠 High: `NodeTopologyConfig` registers its handler on an already-started informer — data race on `eventHandlers`, and the initial zone label can be permanently dropped

| | |
|---|---|
| **File** | `pkg/proxy/config/config.go` (`NodeTopologyConfig`, `newNodeTopologyConfig`, `handleNodeEvent`, `RegisterEventHandler`) · `cmd/kube-proxy/app/server.go` `Run()` (the `NewNodeTopologyConfig(...)` / `RegisterEventHandler(s.Proxier)` block) |
| **Category** | concurrency / initialization |
| **Confidence** | 100 (data-race facet — deterministic) / 75 (missed-initial-delivery facet — scheduling-dependent, but permanent when it triggers) |
| **Found by** | adversarial-reviewer (High), broad-reviewer (Critical) — **validated: confirmed** |

**Issue:**

`NewNodeManager` (in `pkg/proxy/node.go`) starts the single-node informer and waits for its cache to sync **inside `newProxyServer`**:

```go
thisNodeInformerFactory.Start(wait.NeverStop)
if !cache.WaitForNamedCacheSync("node informer cache", ctx.Done(), nodeInformer.Informer().HasSynced) { ... }
```

Later, in `Run()`, `NodeTopologyConfig` attaches its own handler to that **same, already-started** informer and only then registers the proxier:

```go
nodeTopologyConfig := config.NewNodeTopologyConfig(ctx, s.NodeManager.NodeInformer(), s.Config.ConfigSyncPeriod.Duration)
nodeTopologyConfig.RegisterEventHandler(s.Proxier)
```

Adding a handler to an already-started informer makes client-go schedule an **asynchronous synthetic Add replay** of the cached node onto the informer's processor goroutine. Two defects follow, both rooted in the missing synchronization between that replay and `RegisterEventHandler`:

1. **Data race (deterministic).** `NodeTopologyConfig` has **no mutex** (its sibling `ServiceCIDRConfig` in the same file *does*). `handleNodeEvent` reads `n.eventHandlers` in a `for i := range n.eventHandlers` loop on the processor goroutine, while `RegisterEventHandler` does `n.eventHandlers = append(n.eventHandlers, handler)` on the `Run` goroutine — an unsynchronized concurrent read/append that `go test -race` will flag. It is undefined behavior regardless of which goroutine wins.

2. **Initial topology (zone) label can be permanently lost.** If the replay's `handleNodeEvent` runs *before* `RegisterEventHandler` appends the proxier, it sets `n.topologyLabels = {zone: X}` and notifies **zero** handlers. When the proxier is registered a moment later, every subsequent `handleNodeEvent` hits the guard `if reflect.DeepEqual(n.topologyLabels, topologyLabels) { return }` and returns early — so the proxier is **never** told about the initial zone label until an actual zone-label change occurs. Its `topologyLabels` stays empty and zone/topology-aware endpoint categorization (`CategorizeEndpoints`) is silently disabled.

This is **introduced by this PR**: the old code created a *fresh* informer factory in `Run()` and called `Start` only *after* all handlers were registered (the removed comment even read *"This has to start after the calls to NewNodeConfig because that must configure the shared informer event handler first."*). Reusing `NodeManager`'s pre-started informer removed that ordering guarantee.

Severity is High rather than Critical: the worst realistic outcome is a startup data race plus degraded topology routing, not a crash or data loss. The `NodeManager`/`NodeConfig` crash-on-change path is **not** affected — it registers no `AddFunc`, so no replay is delivered into that handler and its slice is not read in the racy window.

**Fix:** restore the "register downstream handlers, then let the informer observe state" ordering, or synchronize the shared state. Either:
- register `s.Proxier` on `NodeTopologyConfig` **before** the informer handler is attached (e.g. have `NewNodeTopologyConfig` accept the handler, or expose registration before `AddEventHandlerWithResyncPeriod` is called), or
- give `NodeTopologyConfig` a mutex (mirroring `ServiceCIDRConfig`) guarding both `eventHandlers` and `topologyLabels`, and deliver the current `topologyLabels` to a handler at registration time so a handler that registers after the replay still receives the initial state.

## Minor Findings

### Residual Risks

- `pkg/proxy/node.go:76` — In `newNodeManager`, the informer factory is started with `wait.NeverStop` and is never stopped on the cache-sync error path (`WaitForNamedCacheSync` returning false returns an error while the factory goroutines keep running). Reported as Critical by go-reviewer, but demoted: `newProxyServer`'s error propagates up through `options.go:374` and terminates the process, and `newProxyServer` runs once — so the goroutines are reclaimed at process exit and cannot accumulate. Practical impact is negligible; it remains a smell in that the informer's lifetime is tied to `wait.NeverStop` rather than the passed `ctx`. (go-reviewer)

## Specialist Notes

### Considered But Not Flagged (all agents)

Items examined and deliberately not reported, with the orchestrator's reasoning (several were reviewer findings dismissed after verification):

- **`pkg/proxy/node.go:108` — returns `err` instead of `pollErr` on poll timeout** (quick-reviewer, anchor 100). **Refuted.** This is intentional (the in-code comment: *"we return the actual error in case of poll timeout"*). Every failing poll iteration sets `err` to the concrete reason (Get error / `GetNodeHostIPs` error / "no PodCIDR allocated"), and with `immediate=true` the condition always runs at least once before the deadline, so `err` is non-nil whenever `pollErr` is — and it is strictly more informative than the generic deadline error. Not a defect.
- **`pkg/proxy/node.go:142-173` — `OnNodeChange` compares old/new IPs and calls `exitFunc` outside the lock** (broad-reviewer, anchor 75). **Refuted.** The comparison operates only on locals (`oldNodeIPs`/`oldPodCIDRs` captured under the lock, and the immutable `node` parameter); the shared `n.node` swap is done under the lock. A single informer delivers events to a handler serially, so `OnNodeChange` is not re-entered concurrently, and `Node()` takes the lock for a consistent snapshot. No race.
- **`pkg/proxy/healthcheck/proxy_health.go` — `NodeEligible()` dereferences `hs.nodeManager` with no nil guard** (broad-reviewer Medium; also examined and dismissed by adversarial and go). Not reachable in current control flow: `NewProxyHealthServer` is only called from `newProxyServer`, which always constructs a non-nil `NodeManager` first (returning on error); hollow-proxy leaves `HealthzServer` nil and never calls `NodeEligible`. A defensive-programming suggestion, not an introduced bug — and out of scope under `reach=narrow`.
- **`pkg/proxy/config/config.go` — `handleChangeNode` contains a `DeletedFinalStateUnknown` tombstone branch, but is registered only on `UpdateFunc`** (quick-reviewer, adversarial-reviewer). Tombstones are delivered only via `DeleteFunc`, so the branch is unreachable defensive code — harmless, no wrong behavior.
- **`NodeManager` may miss a NodeIP/PodCIDR change occurring in the construction→handler-registration window** (adversarial-reviewer). Bounded, not lost: `NodeConfig` has no `AddFunc` so the replay is dropped, but the next real Update — or the resync at `ConfigSyncPeriod` — re-delivers the node as an Update, compares against the construction snapshot, and exits. Detection is delayed by at most one resync period, not permanently missed.
- **Slice aliasing from `PodCIDRs()` / `NodeIPs()` returning under the mutex** (go-reviewer). No live aliasing hazard: the returned slices are consumed once at startup and not mutated afterward.
- **Topology-label map shared by reference across ipv4/ipv6 proxiers via metaproxier** (go-reviewer). Safe: `handleNodeEvent` allocates a fresh map on each event and never mutates it after publishing, so handlers holding the reference never observe a torn/mutated map.
