### #1 🔴 Critical: `quoteIdentifierIfNecessary(vars[0])` throws when `refIds` is empty, crashing the expression editor

| | |
|---|---|
| **File** | `public/app/features/expressions/components/SqlExpressions/SqlExpr.tsx:81` |
| **Category** | correctness / null-safety |
| **Confidence** | 100 |
| **Found by** | test-reviewer (Critical), quick-reviewer (High), adversarial-reviewer (High), typescript-reviewer (High), security-reviewer (High) |
| **Validation** | confirmed |

**Issue:** `vars` is `refIds.map((v) => v.value!)` (line 61), so `vars[0]` is `undefined` when `refIds` is `[]`. The newly imported `quoteIdentifierIfNecessary` (`public/app/plugins/datasource/mysql/sqlUtil.ts:44`) delegates to `isValidIdentifier`, which calls `identifier.toUpperCase()` unconditionally at `sqlUtil.ts:54` — a `TypeError` on `undefined`. `initialQuery` is computed in the component body on every render, so the render itself throws. Before this change the same state interpolated the harmless string `"undefined"`.

Empty `refIds` is a state this component tree explicitly anticipates: `ExpressionQueryEditor.tsx:117` computes `refIds` as `queries!.filter((q) => query.refId !== q.refId)`, and two sibling components in the same directory guard it — `GenAI/GenAISQLSuggestionsButton.tsx:103` (`disabled={refIds.length === 0}`) and `SchemaInspector/SchemaInspectorPanel.tsx:174`. `SqlExpr` does not.

**Verified:** a scratch test rendering `<SqlExpr onChange={jest.fn()} refIds={[]} query={{refId:'expr1',type:'sql',expression:''}} queries={[]} />` throws `Cannot read properties of undefined (reading 'toUpperCase')`. With line 81 reverted to `${vars[0]}` and nothing else touched, the same test does not throw. (Probe run under the Step 4.5 protocol; tree restored byte-identically and all three suites re-confirmed green.)

**Blast radius differs by path**, established by the validator:
- Dashboard / panel-edit: **contained**. `QueryEditorRow.tsx:528` wraps the plugin editor in `<ErrorBoundaryAlert boundaryName="query-editor-operation-row">`, so only that query row breaks.
- Alerting rule editor: **not contained**. No local boundary exists around `Expression` / `ExpressionsEditor` / `QueryAndExpressionsStep` / `AlertRuleForm`, so the throw reaches `AppWrapper.tsx`'s page-level `ErrorBoundaryAlert`, replacing the whole page and discarding in-progress rule edits. Reachable in a few clicks: new Grafana-managed rule → delete the default data query → *Add expression* → *SQL*. `addNewExpression` (`.../query-and-alert-condition/reducer.ts:145`) does not require any data query to exist, and the *Add expression* button (`QueryAndExpressionsStep.tsx:617`) is gated only on `config.expressionsEnabled`.

**Severity:** rated Critical on consolidation rule 3 (highest severity among finders wins; a specialist's Critical is not outvoted) plus the validator's blast-radius evidence. **Dissent recorded**: four of five finders rated it High, and the validator called High "not an underestimate." If the alerting path is judged out of scope, High is defensible — the verdict is NEEDS_CHANGES either way.

**Fix:** guard the call site, and add the missing case to `SqlExpr.test.tsx`.

```tsx
FROM
  ${vars[0] ? quoteIdentifierIfNecessary(vars[0]) : ''}
```

Hardening `isValidIdentifier` against non-string input would also close it, but that helper is shared with the MySQL datasource, so the call-site guard is the narrower change.

### #4 🟡 Medium: the quoting helper this change now depends on does not escape embedded backticks

| | |
|---|---|
| **File** | `public/app/plugins/datasource/mysql/sqlUtil.ts:44` (as newly relied on by `SqlExpr.tsx:81`, `sqlCompletionProvider.ts:27`, and by the twin at `metaSqlExpr.ts:114`) |
| **Category** | correctness (input neutralization) |
| **Confidence** | 100 |
| **Found by** | adversarial-reviewer (Medium), security-reviewer (Medium), test-reviewer (Medium) |
| **Validation** | waived — probe-confirmed and corroborated ×3 |

**Issue:** the helper wraps the value in backticks without doubling backticks already inside it, which is MySQL's own escaping rule. The change makes three new call sites depend on it as if it were a complete neutralizer. Query refIds are free text (`QueryEditorRowHeader.tsx:52-70` enforces only non-empty and unique), and provisioned or imported dashboard/rule JSON is unconstrained.

**Verified** by evaluating the helper's exact expression:

| refId | generated SQL |
|---|---|
| `` A` , `B `` | `` SELECT * FROM `A` , `B` LIMIT 1 `` — two table references |
| `` A` UNION SELECT * FROM `B `` | `` SELECT * FROM `A` UNION SELECT * FROM `B` LIMIT 1 `` |
| `` a`b `` | `` SELECT * FROM `a`b` LIMIT 1 `` — malformed |

**This is not a privilege boundary.** The security-reviewer established that the generated SQL runs in-process against go-mysql-server (`pkg/expr/sql/db.go`) with `IsReadOnly: true` and file writes disabled, over only the frames returned by the other queries in the same `/api/ds/query` request (`frame_db.go:30-40`), all of which the requesting user already authorized. `INTO` is rejected by the node allowlist (`parser_allow.go:112-115,132`). So the realistic outcome is a broken or silently reshaped query the user aimed at themselves, not cross-user data reach — which is why this is Medium and not a security finding.

**Fix:** double embedded backticks when quoting, and teach `unquoteIdentifier` (`sqlUtil.ts:59`) to collapse them back so the emit/read pair stays symmetric.

```ts
export function quoteIdentifierIfNecessary(value: string) {
  return isValidIdentifier(value) ? value : `\`${value.replace(/`/g, '``')}\``;
}
```

### P1 🟢 Low: quoted table identifiers do not round-trip through the plugin-ui tokenizer, so column autocomplete stays silently empty for spaced names

| | |
|---|---|
| **File** | `public/app/features/expressions/utils/metaSqlExpr.ts:15`, `public/app/features/expressions/components/SqlExpressions/CompletionProvider/sqlCompletionProvider.ts:27` |
| **Category** | correctness / silent failure |
| **Confidence** | 100 |
| **Found by** | broad-reviewer (Critical), adversarial-reviewer (Medium) |
| **Validation** | confirmed, **reattributed to pre-existing** — severity corrected from Critical to Low |

**Issue:** the completion inserts a backtick-quoted table name into the Monaco buffer, but the delimiter is tokenized as its own token, so the `TableIdentifier` handed back to `columns.resolve` holds a lone backtick rather than the name.

**Verified** by tokenizing with Monaco's built-in mysql Monarch grammar. `` SELECT * FROM `gdp per capita` LIMIT 1 `` yields `keyword("FROM")`, `white`, **`identifier.quote("` ")`**, `identifier("gdp per capita")`, `identifier.quote`, … `getTableToken` returns `fromToken.getNextNonWhiteSpaceToken()` — the opening backtick — and `defaultTableNameParser` splits its value on `.`, giving `{ table: '`' }`. `LinkedToken`'s `isWhiteSpace`/`isKeyword`/`isVariable` compare against `white.sql`/`keyword.sql`/`variable.sql`, none of which match `identifier.quote.sql`, so the delimiter is not skipped; and `sqlCompletionProvider.ts` supplies no `tables.parseName` override to intercept it. `fetchSQLFields` then builds `` SELECT * FROM ``` LIMIT 1 `` and `queries.filter((q) => q.refId === '`')` matches nothing; the failure is swallowed by `catch { return []; }`.

**Why this is pre-existing, not a regression** — the decisive point, and why broad-reviewer's Critical does not stand: before the change the completion inserted the name **unquoted**, so the buffer read `FROM gdp per capita`, which tokenizes to `{ table: 'gdp' }` and built `SELECT * FROM gdp LIMIT 1` — failing identically and just as silently. Column autocomplete was already broken for spaced identifiers; the change alters which wrong string is passed, not the outcome, while fixing the actual reported bug (the main query was syntactically invalid before). It is also behind the default-off experimental `sqlExpressionsColumnAutoComplete` toggle.

**Note on the two finders' mechanism accounts:** broad-reviewer attributed this to `@grafana/plugin-ui` registering its own `standardSql` grammar with no backtick rule. That is wrong — `resolveLanguage` (`SQLEditor.js:95-101`) resolves `id: 'mysql'` against Monaco's own registry, and `mysql.js:866-870` does support backticks. adversarial-reviewer's account is the correct one. This matters for the fix: the root cause is an upstream `tokenUtils` limitation affecting every consumer that omits `tables.parseName`, not a missing grammar rule.

**Suggested direction (not required by this change):** mirror the MySQL datasource, which unquotes before use (`mySqlMetaQuery.ts:38-39` → `sqlUtil.ts:59` `unquoteIdentifier`) — or supply a `tables.parseName` that reassembles the quoted token span.

## Specialist Notes

### Threat Model Notes (security-reviewer)

- **Trust boundaries.** Two. (1) Stored/imported/provisioned dashboard and rule JSON → the editor: `refId` strings arrive from that JSON and are interpolated into SQL text. (2) `POST /api/ds/query` → the backend expression engine, where `AllowQuery` (`parser_allow.go:13`) is a genuine node-and-function allowlist.
- **What the generated SQL executes against.** Not a real database. `NewFramesDBProvider` (`frame_db.go:30`) builds a database whose only tables are the data frames returned by the other queries **in the same HTTP request**, keyed by refId. The reachable data is exactly the requesting identity's own authorized query results. This is the single most severity-limiting fact in this review and is why finding #4 is Medium rather than a vulnerability.
- **Server-side controls that survive a frontend quoting gap.** Read-only engine, file writes disabled, `INTO` rejected directly and on `SetOp` (`parser_allow.go:112-115,132`), plus `SQLExpressionQueryLengthLimit`, cell limits and `SQLExpressionTimeout` (`sql_command.go:89,96`). `UNION` and subqueries are permitted, so an injected construct can be *shaped* but cannot reach outside the frame set or write anything.
- **`queries.filter((q) => q.refId === query.table)` is not an authorization control** and the change did not weaken it. A non-matching table sends zero frames and the backend then fails dependency resolution (`NeedsVars` from `TablesList`, `sql_command.go:47,101`) rather than widening. It is a payload-size optimization.
- **Net attack-surface change**: a reduction for the intended case (identifiers with spaces now parse), with two new sharp edges — the unhandled `undefined` of finding #1, and a control incomplete against the one character it is built from (finding #4).
- **Assumptions stated by the reviewer**: the Go engine was not executed against a crafted query; the allowlist conclusions come from reading `allowedNode`/`allowedFunction` case by case.
